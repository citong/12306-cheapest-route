# 旅游攻略模块 · 设计方案（草案）

> 目标：在现有「12306 最便宜火车路线」基础上，长出一个**以目的地为中心的行程规划 + 住宿推荐**功能，
> 从「查一段路」升级成「排一趟旅行」。交通（火车）成为行程里的第一天 / 最后一天。
>
> 状态：**草案，待拍板**。作者：Claw 会话（手机端）。桌面端会话如接手，请先读本文件。

---

## 1. 与现有功能的关系

| | 现有 | 新增 |
|---|---|---|
| 输入 | 出发地 → 目的地 + 日期 | 出发地 → 目的地 + 日期 + **天数 + 偏好** |
| 输出 | 最便宜的火车换乘方案 | **N 天行程表**（每天去哪、怎么走、住哪、花多少）+ 火车去返程 |
| 页面 | `index.html` 查询、`map.html` 车站地图 | 新增 `trip.html` 行程页 |

不是推倒重来，是**并列加一个页签**，复用现有一切（车站数据、本地服务、离线兜底、地图 key）。

## 2. 架构（沿用现有三段式）

现有：静态单文件页（数据内嵌、零依赖） + 本地服务 `127.0.0.1:8787`（实时查询） + 离线兜底。

新增保持同款：

```
scripts/trip_template.html   # 行程页模板（新）

data/poi/{城市}.json         # 景点 / 酒店 POI 缓存（新）
data/attr_extra.json         # 人工补充：开放时间 / 门票 / 建议时长 / 预约要求（新）
```

导航：顶部在「路线 / 地图」旁加一个「✈️ 行程」。

## 3. 数据来源 —— 关键决策点

行程规划的一切都建立在 **POI（兴趣点）** 之上：景点、酒店、餐厅，要经纬度、评分、营业信息。

### 方案 A：腾讯地图（推荐，项目已在用）
`map.html` 已经在用腾讯地图 TMap JS API。
- 能用：地点搜索、**周边搜索**、逆地址解析、**路线规划（步行/驾车/公交）**、POI 评分与坐标
- 拿不到：**酒店实时房价 / 房态**、部分景点开放时间
- 需要：一个 WebService key（在腾讯位置服务控制台免费申请，个人额度日常够用）

### 方案 B：高德地图
POI 质量与路线规划同样强，接口更成熟。多申请一个 key，二选一即可。

### 方案 C：纯自建数据集
5A/4A 景区名单是公开信息，可整理；但酒店、餐厅、实时路况没有，覆盖窄。**不建议单独用**，可作为补充。

> **结论**：A（或 B）+ C（补充开放时间/门票）。

---

## 4. 必须正视的硬约束（先说清楚，免得做到一半发现做不了）

1. **酒店价格拿不到。**
   携程/美团/飞猪的房价是商业数据，无公开 API、反爬严格，爬取既不稳定也不合规。
   我们能合法且稳定做到的**上限**是：
   - 展示酒店 **名称 / 位置 / 评分 / 价格区间（部分 POI 有人均）**
   - 点「查看房型」→ **跳转携程/美团带参搜索页**（城市 + 入住/离店日期 + 关键词），用户在那边下单
   - 不要试图在站内渲染实时房价。

2. **景点开放时间 / 门票 / 预约要求，地图 POI 通常没有。**
   需要一张人工维护的补充表（`data/attr_extra.json`），例如：
   ```
   "北京": { "故宫博物院": {"open":"08:30-17:00", "closed":"周一", "ticket":60, "need_reserve":true, "dur":180} }
   ```
   先覆盖 10~20 个热门旅游城市，每城 5A + 主要 4A。

3. **地图 API 有日调用上限** → 必须缓存，和现有 `train_cache_graph.json` 一个思路。
   同一个城市的 POI 拉一次存本地，之后离线可用。

4. **12306 的坑照旧**（限流、跨天车次、日期绑定票价），交通那一段直接复用现有逻辑，不重写。

## 5. 行程编排算法（核心，纯 Python 可实现）

输入：城市 POI 列表（经纬度、评分、类型、建议时长）、天数 N、每天可玩小时、偏好权重、住宿点。

1. **打分**：`评分 × 偏好权重 × 热度`，偏好如 自然/历史/美食/亲子。
2. **地理聚类**：按经纬度把候选景点分成 N 组（每天一组），避免来回穿城 —— 贪心聚类即可，不必上 KMeans。
3. **组内排序**：以住宿为起点，最近邻 + 2-opt 微调，得到当天动线（近似最短路径）。
4. **时间轴填充**：09:00 起，按「建议时长 + 通勤时间」顺排；在饭点自动搜附近餐厅 POI 插入。
5. **输出**：
   ```json
   { "day": 1, "items": [
     {"t":"09:00","poi":"西湖","act":"游览","dur":120,"transit":"步行 8 分钟"},
     {"t":"12:00","poi":"楼外楼","act":"午餐","dur":60}
   ], "hotel": "…", "cost": {"ticket":0,"meal":120,"hotel":400} }
   ```
6. **可解释**：给一句「为什么这么排」（地理集中、避开周一闭馆、餐厅顺路）。

## 6. 住宿推荐逻辑

- **候选来源**：地图 API 的酒店 POI；也可用**「地铁站/火车站/商圈」聚合**（能复用现有车站与城市数据）。
- **打分维度**：离景点群重心距离、评分、价格区间、品牌、交通便利度（近地铁/火车站）。
- **呈现**：地图打点 + 卡片列表（名称/评分/区间/距核心景点几分钟）+ 「去哪儿看房」跳转。
- **每晚建议**：默认选 1 家；也可按预算给「经济/舒适/高档」三档。

## 11. 最简 v1 详细实施计划（拍板后按此建）

> 目标：用**最小成本**跑出一个能看的旅游攻略页。不申请新 key、不接实时 POI、不加后端。
> 先把「自动分天 + 每日动线 + 酒店跳转」跑通，再迭代。

### 11.1 新增文件

```
trip.html                       # 生成物，发布到 Pages（数据内嵌，零依赖）
scripts/trip_template.html      # 行程页模板（仿 site_template.html）
scripts/render_trip.py          # 模板 + 数据 → trip.html（仿 render_site.py，纯注入）
scripts/planner.py              # 离线编排算法（纯标准库，无依赖）
data/attractions/杭州.json       # 景点清单（AI 用公开资料预填，可手工改）
data/trip_built.json            # planner.py 产出，render 时内嵌进页面
```

> 不引入新 Python 依赖；planner.py 只用 `math`/`json`/`random`。
> 数据内嵌进 trip.html，避免 `file://` 下 CORS 加载 JSON 失败（沿用现有 render 思路）。

### 11.2 数据层：`data/attractions/杭州.json`

```json
{
  "city": "杭州",
  "center": [120.155, 30.274],
  "days_suggest": 3,
  "spots": [
    {"name":"西湖","lat":30.259,"lng":120.149,"dur":180,
     "tags":["自然","免费","必去"],"open":"全天","ticket":0,"note":"建议上午，环湖步行/游船"},
    {"name":"灵隐寺","lat":30.242,"lng":120.101,"dur":150,
     "tags":["历史","宗教"],"open":"07:00-18:00","ticket":75,"note":"需先买飞来峰门票"},
    {"name":"河坊街","lat":30.241,"lng":120.170,"dur":90,
     "tags":["美食","购物","夜游"],"open":"全天","ticket":0,"note":"晚上更热闹"}
  ]
}
```

字段说明：`dur`=建议游览分钟；`tags`=用于偏好过滤；`open`/`ticket`=开放时间与门票（人工补）；
`note`=页面提示。首期一个城市 15~25 个 spot 即可。

### 11.3 算法：`scripts/planner.py`（离线，构建时跑）

输入：`spots`、天数 `N`、每天可玩小时 `H=8`、偏好权重 `prefs`、可选住宿点。
输出：`trip_built.json`。

步骤：
1. **过滤/打分**：`score = 基础分 × Σ(命中偏好权重)`；按 score 取前 K 个（K ≈ N×日均上限）。
2. **地理聚类分天**：取 N 个相距最远的 spot 作种子 → 其余按最近种子归组 → 迭代 2~3 次收敛
   （避免同天景点跨城跑）。无 scipy，用纯 Python 实现 k-means 雏形即可。
3. **组内排序**：以当天几何中心（或住宿点）为起点，最近邻串联 + 2-opt 微调，得当天动线。
4. **时间轴填充**：09:00 起，依次排 `dur`；相邻两点的通勤分钟用 `距离 × 经验速度`估算
   （步行 5km/h、公交 15、驾车 25，先不调接口，留 TODO 接腾讯路线规划）。
5. **午/晚餐**：在 12:00、18:00 附近插一个 `tags 含 美食` 的 spot 作「午餐/晚餐推荐」（可选）。
6. **费用估算**：门票合计 + 餐饮（人均 × 餐数）+ 酒店区间（来自酒店数据，仅区间）。

输出结构（节选）：
```json
{"days":[
  {"day":1,"center":[...],"items":[
     {"t":"09:00","name":"西湖","dur":180,"transit":0,"note":"..."},
     {"t":"12:30","name":"楼外楼","dur":60,"transit":12,"kind":"meal"}
  ],"cost":{"ticket":0,"meal":120}},
  ...
]}
```

### 11.4 页面：`scripts/trip_template.html` → `trip.html`

- **顶部输入栏**：城市下拉（先写死支持的城市列表）、天数（1~7）、偏好多选
  （自然/历史/美食/亲子/购物/免费）、出发日期（用于酒店跳转带参）。
- **主体**：横向 day tab + 当天时间轴卡片（时间 / 景点 / 游览时长 / 交通分钟 / 备注）。
- **费用条**：每日门票 + 餐饮估算 + 酒店区间。
- **酒店区（最简）**：不做 POI 列表，直接一个「在携程查看 {城市} 酒店」按钮，
  链接 = `https://www.ctrip.com/hotels/list?city=...&checkin=...&checkout=...`（按输入日期拼）。
  申请到地图 key 后再升级成「附近酒店卡片」。
- **地图（可选，M2 做）**：复用现有腾讯 TMap，把当天 spot 标点连成线。
- **风格**：沿用 index.html 的配色/卡片风格，保持一致。

### 11.5 与现有站点整合
